## Design (no architecture change)

1. **Override record** `jobs/<job>/cad_check_override.json` (v2/cad_check_override): `POST /api/v1/jobs/{id}/check/override`
   (Admin, body `{reason}`), `DELETE` (Admin), `GET` (all roles: `{override, valid, problem}`). Written in the job run
   slot (409 `run-busy` while a run is active, so no check / plan run can change the inputs meanwhile).
   `findings` = names of the static objects hit in check 4 (`values.hits[].static`, else the note);
   `cad_check_sha256` = SHA-256 of the current `cad_check.json`; `inputs` = that file.
   POST refused (409 `override-not-applicable`) when check 4 is not red or any other check is red; 409
   `cad-check-stale` / `cad-check-missing` as for the gate.
2. **Gate** `cad_api.cad_gate(job, root, collision)` returns the override reference or None. Red passes only when
   check 4 is the only red check, the check is current, the override validates and its `cad_check_sha256` equals the
   current file, and the request is collision `off`. Otherwise: existing 409s; new 409 types
   `cad-check-override-void` (override present, check changed), `cad-check-override-invalid` (schema),
   `cad-check-override-kinematic-only` (collision on with an override). `PlanRequest.collision` (`off` default, `on`
   refused with 409 `collision-unavailable`: Goal 2, CP-58).
3. **D07 / D09 record** (least invasive, no CLI change): the plan run's `on_success` writes
   `cad_check_override {file, sha256, cad_check_sha256, check_id: 4}` into the run's `path.json` before promotion
   (validated against the v2/path property schema; refused if the override file changed meanwhile). The program
   run's `on_success` copies the field from the job `path.json` into the new `program.json` when the program records
   that exact `path.json` hash (validated against the v2/program property schema). Request to planner /
   program-verify: carry the field natively (`--cad-check-override <file>`), then the runner step becomes a no-op.
4. **S2**: check-4-only red message names the static objects (CAD cause, OI-23, fix in the cell CAD or the S10 / job
   roles); Admin form "Override for kinematic planning (CP-62)" with reason; banner "overridden for kinematic planning
   by <admin> at <time>: <reason>"; void override shown; the Selection panel says why "New seam" is unavailable.
   Logic in `lib/cadcheck.ts` (vitest).
5. **Stale texts (m3)**: S1 create-job note and the backend no-placement note follow CP-60 (job assembly → roles,
   axis, cross-check → placement `job_cad`; single-part upload → manual placement test helper, Assumption).
6. **S10 (m4)**: `GET /cell/model` returns `head.tcp` (taught tool0_T_tcp, beam axis, method, by, at, edge, stick-out)
   from head.yaml; S10 shows them and "head CAD present"; the roles refusal is shown once (list under the tree).
7. **S1 (m6)**: up-axis default = the cell up axis (`GET /cell/model` `up_axis`) when a cell STEP exists.
