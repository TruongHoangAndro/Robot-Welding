# WP-S S.5c — H-CAD head model from the Fusion head CAD — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the TST-002 §3.1 box head (H-BOX) by an option `head_model = H-CAD` whose head body and mount come
from the Fusion CAD, then re-run J2 (robot-only and Mode B screening) and G2 with it, so the meeting of Fri 2026-11-06
sees whether the box envelope causes the J2 failure.

**Architecture:** `awm_geometry` (conda, ADR-15) reads the head assembly, estimates `tool0` and `tcp_laser` from the
geometry, and writes tool0-frame meshes plus `head.yaml` into `<repo>/cell/model/head/` (D14 meshes generated by A18,
ADR-16). `awm_description` gets a second head macro with the **same link names** as H-BOX, so SRDF / ACM, padding,
clearance link set and F9 stay unchanged; the head is chosen by a launch / xacro argument. The planner reads
`tool0_T_tcp` from the robot description (one source), never from a constant.

**Tech Stack:** pythonocc-core 8.0.1 (conda `awm_occ`), numpy, xacro / URDF meshes (file://), MoveIt 2 Jazzy, pytest.

**Spec:** PLAN.md WP-S S.5 ("two head models (CAD hulls; TST-002 §3.1 box)"); DES-001 Rev 0.5 §5.4 (head + mount from
D21, convex hulls, nozzle split `nozzle_tip` / `nozzle_body`, 3 mm padding), ADR-16, CP-56 (nozzle = cell data);
TST-002 Rev 0.2 §3.1, §7 step 2; scene decisions `docs/generated/spike/scene_decisions.md` (D6, D7).

## Global Constraints

- Simulation only (mock hardware). No real robot, PLC, LightWELD or laser; no IP addresses.
- Units mm / deg in project data; m / rad only through `awm_core.units` (URDF mesh `scale="0.001 0.001 0.001"` is the
  allowed URDF unit statement, as in the existing cell meshes).
- No absolute paths in source: head folder comes from a launch / xacro argument (`head_dir`), like `cell_manifest`.
- No part- or head-specific names in source: component names live in a map file
  `docs/generated/spike/cad_map_head.yaml` (schema `cad_map/0.1`, `head_cad: 'ASSY, Welding tool:1'`, depth 1).
- Source STEP: `docs/3D/Dau_han_robot.step` (Fusion, AP214, mm, up axis to be stated in the map). Never modified.
- **tool0 / TCP = Assumption, estimated from geometry (lead proposal (a), 2026-11-05; confirm with Truong)**; every estimate can be
  overridden in the map (`frames.tool0`, `frames.tcp`: point + axis in file mm) and is recorded with method and residual.
- Nozzle stays a parametric cylinder (CP-56: nozzle is cell data; Ø 20 × 40 default, I2 / OI-15) placed on the CAD
  beam axis; `nozzle_tip` = last 5 mm, collision stops s_c 0.3 mm before `tcp_laser` (unchanged F9 geometry).
- H-BOX stays the default; existing records (S.4–S.6, S.5b) must stay reproducible.
- `docs/reference/**`, `docs/LLM_Wiki/**` read-only. ROS commands only via `scripts/dx`. Never push or merge.

## Review Focus

1. Head CAD is a surface model (LightWELD = compound, 0 solids) — tessellation must not drop faces; hull and mesh both
   built from all faces (test: face count in = faces covered, as `_tessellate_mm` hull mode).
2. tool0 yaw about the flange axis is not fixed by a flat face — must be taken from a non-symmetric feature or recorded
   as Assumption (a wrong yaw only shifts q6 by a constant, ψ sweep absorbs it, but wrist-3 limits shift).
3. Fusion file has the robot posed: the head must be expressed in the **mount flange** frame, not in file frame (test:
   synthetic assembly with a rotated flange gives the same tool0-frame mesh).
4. The 611 mm LightWELD extent may include a cable stub: report which part of the mesh lies behind the head body; do
   not silently cut it.
5. `tool0_T_tcp` used by IK must equal the URDF chain tool0 → tcp_laser for both head models (test in planner).
