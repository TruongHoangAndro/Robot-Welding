# WP-S S.2 — M4 core: KinematicsBackend and SceneBackend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Start the M4 core library (pure Python, no rclpy, mm / degrees) with its two backend interfaces: analytic UR5e
kinematics returning all IK solutions, and a scene-validity backend on `move_group`.

**Architecture:** New sub-package `awm_path.core` holds the protocols and the pure implementations; it never imports
rclpy. ROS-bound implementations live in `awm_path.backends` and wrap the existing `MoveItClient`. All public
values are mm and degrees; conversion to m / rad goes only through the new `awm_core.units` (ADR-14). S.3 (state space,
labels, ladder DP) and S.4 (clearance, closest pair, contact) build on these interfaces and are not part of this plan.

**Tech Stack:** Python 3.12 (ROS 2 Jazzy, `awm_dev`), numpy, `ur-analytic-ik==0.1.0.post3` (venv), MoveIt2 `move_group`
services through `awm_path.moveit_client.MoveItClient`, pytest via colcon.

**Spec:** `PLAN.md` §3 WP-S row S.2; DES-001 Rev 0.6 DRAFT §4.3 (M4 core paragraph) and the dependency rule (B-06,
CP-41) in `docs/generated/drafts/APLSMN601-DES-001_Software_Architecture_Rev0.6_DRAFT.md`; TST-002 Rev 0.3 DRAFT §1–§3
(`docs/generated/drafts/APLSMN601-TST-002_Collision_Avoidance_Spike_Rev0.3_DRAFT.md`).

## Global Constraints

- Branch `ws-s2-m4-core` from `GotoCode`, in the main workspace (no git worktree). Commit prefixes `env:`, `awm_core:`, `awm_path:`.
- Every ROS / colcon / pytest command runs through `scripts/dx "<cmd>"` (container `awm_dev`). Nothing installed on the host.
- Simulation only (mock hardware). No real robot, PLC, LightWELD or IP address.
- Units (ADR-14): public API of `awm_path.core` = mm and degrees. m / rad only inside implementations, converted only with
  `awm_core.units`. No `* 1000`, `/ 1000`, `math.radians`, `np.deg2rad` outside `awm_core/units.py`.
- `awm_path.core` must not import `rclpy`, `moveit_msgs` or any ROS message package (B-06).
- `ur-analytic-ik` pinned at `0.1.0.post3`, installed in a venv inside `awm_dev`, mirrored in `docker/Dockerfile`.
  Never `pip install` into the system Python.
- IK vs FK acceptance: position error < 0.01 mm, rotation error < 1e-6 rad (PLAN.md S.2).
- Pose frame of `KinematicsBackend` = `base_link` of `ur_description` → `tool0` (the frames MoveIt uses). Any offset of the
  library's own base frame (UR `base` = `base_link` rotated 180° about Z, DES-001 §5.3) is absorbed inside the implementation.
- Joint order = `shoulder_pan, shoulder_lift, elbow, wrist_1, wrist_2, wrist_3` (6 values; the positioner joint is not part of S.2).
- Allowed test skip: only `AWM_CELL_STEP not set`. A missing `ur_analytic_ik` is a failure, not a skip.

## Review Focus

1. Pose at a wrist singularity (wrist_2 = 0°): IK may return duplicated or degenerate solutions → every returned solution is finite and passes FK < 0.01 mm (Task 3, `test_ik_at_wrist_singularity_returns_only_valid_solutions`).
2. Unreachable pose (target 2000 mm from the base) → empty list, no exception (Task 3, `test_ik_unreachable_returns_empty`).
3. Joint angles outside (-180°, 180°] (e.g. wrist_3 = 350°) → the original state is found among the IK solutions modulo 360° (Task 3, `test_ik_contains_original_state_modulo_360`).
4. Pose given in metres or with a non-orthonormal rotation → `ValueError` (Task 3, `test_ik_rejects_non_rigid_transform`); position in metres is caught in Task 2 only by naming (`*_mm`), so the docstring states the unit.
5. State with 7 joints (robot + positioner) passed to the 6-joint scene backend → `ValueError`, never truncated (Task 5, `test_check_rejects_wrong_joint_count`).
